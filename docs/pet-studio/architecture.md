# 宠物工坊技术架构

> 状态：方案，尚未实现。对应[产品需求](requirements.md)。以下路径和数据结构是实施目标，不代表当前版本已经支持。

## 1. 当前链路与关键缺口

`src/electron/main.js` 目前负责导入、5 MB 大小限制、格式识别、自动抠图、写入本地副本和立即选用。`settings-store.js` 保存自定义宠物的 id、名称、扩展名与类型。`artwork-source.js` 把自定义素材编码为图片 data URL；桌面 `ArtworkPlayer` 显示图片或内置 WebM。静态图的动态感主要来自 `pet.css` 对整张图的变换。

现有透明 WebM + `pet://` 协议适合**已制作好的逐帧动画**，应继续保留。用户单图需要的是可以即时调参、预览并长期编辑的作品数据；单纯把整图离线转成 12 帧 GIF/WebM 不能解决头脸与肢体的结构问题，还会让后续编辑困难。

当前导入对 GIF 原样保存；非 GIF 则尝试静态抠图。若动态 WebP 或 APNG 被静态解码、再编码成 PNG，就会丢失后续帧。本轮先在格式识别后分流，保留 GIF/动态 WebP/APNG 原文件。多文件帧序列和视频仍没有导入入口。

## 2. 渲染与制作的分层方案

| 路径 | 输入 | 运行时 | 用途 |
| --- | --- | --- | --- |
| 现有素材播放 | 内置 WebM/GIF、用户 GIF/动态 WebP | 现有 `ArtworkPlayer` | 已有逐帧动画保持原样，不叠加自动形变。 |
| 用户帧序列（P1） | 有序 PNG/WebP + 时长清单 | 时间轴播放器，必要时离线编码 | 保留每帧的姿态与时长，支持状态映射。 |
| 用户透明视频（P1） | 验证通过的 WebM | 受控 `pet://` 流 + `<video>` | 直接复用现有透明视频播放链路。 |
| 单图自动动效（P0） | 用户确认的透明主体 + 蒙版 | GPU 网格形变；失败时显示静态图 | 小幅呼吸、重心和摇摆，单张图即时可用。 |
| 分层绑定（P2） | 多图层、锚点、遮挡和动作曲线 | 同一渲染核心的多网格场景 | 抬手、走路等需要补全遮挡的动作。 |

P0 优先评估 [PixiJS MeshPlane](https://pixijs.download/v8.21.0/docs/scene.MeshPlane.html)：网格顶点可实时更新，PixiJS 是 [MIT 许可](https://github.com/pixijs/pixijs)；限定只在一只桌宠与工坊预览中创建 GPU 场景，避免市场列表同时运行多路动画。采用成熟的 WebGL 渲染后端，持续测量透明 Electron 窗口中的边缘、内存与 GPU 占用。Canvas/WebGL 初始化失败时保持原静态素材可用。

帧序列与视频属于**已经有动作的素材**，不经过 PixiJS 单图网格。帧序列保存有序文件和逐帧时长，播放器用经过时间计算出的帧号而非每次绘制加一；先预解码有限数量的相邻帧，较长作品离线编码以避免把全部 RGBA 帧常驻内存。[FFmpeg 的 image2 输入](https://ffmpeg.org/ffmpeg-formats.html)可作为离线编码参考，但发行版是否附带转码器须以体积、许可与跨平台实测再决定。透明视频先复用现有 `<video>` 与 `pet://` 流式协议；[Electron 协议文档](https://www.electronjs.org/docs/latest/api/protocol)明确要求媒体协议启用 stream。视频源按容器、编码、时长、尺寸、解码结果及首帧 alpha 检查，失败时不给用户展示虚假的透明预览。

[Inochi2D](https://github.com/Inochi2D/inochi2d) 展示了分层纹理与网格绑定的成熟结构，可参考作品数据和编辑概念；其主 SDK 不是当前 Electron/TypeScript 的直接运行时。[Live2D Cubism Web SDK](https://docs.live2d.com/en/cubism-sdk-manual/cubism-sdk-for-web/) 的核心受专有许可约束，现阶段不作为免费开源桌宠的默认依赖。参考项目的设计思想，不复制模型、素材或未经核对授权的实现。

## 3. 作品模型与边界

建议在 `userData/pets/<id>/` 维护可版本化的项目目录：

```text
pet.json             schemaVersion、名称、原始格式、制作模式、当前动作参数
original.<ext>       用户导入时的原始图片副本
subject.png          用户确认过的透明主体
mask.png             可再次修边的蒙版（需要修边时）
thumbnail.png        市场和小窝用的静态缩略图
frames/              P1 连续帧素材，顺序与时长写在 pet.json
motion.webm           P1 验证通过的视频素材（存在时）
layers/              P2 才创建的分层素材
```

`pet.json` 只引用目录内受控文件名，主进程按作品 id 解析路径。主进程继续独占文件读写、格式与尺寸校验、项目版本迁移；React 页面通过独立 preload 与 IPC 读取预览数据、提交编辑，不直接访问 Node 或任意文件路径。作品写入用临时目录/文件加原子替换，失败时保留上次可用版本；删除作品时按当前确认流程执行。

作品类型应明确区分 `single-image / animated-image / frame-sequence / transparent-video / layered`，并可把一个或多个素材绑定到 `idle / walk / tap / play / nap`。每段素材记录原始循环、时长与用户设置，主进程校验文件数量、解码像素总量和目标路径；不要只凭扩展名或上传文件大小判断安全与性能。市场和小窝通过 `thumbnail.png` 获取静态预览，避免列表同时解码多段视频。

当前设置中的 `customPets` 不立即改名或删除。升级版先按 id 查找项目；没有项目目录的旧作品照旧通过现有素材路径使用。用户主动编辑旧作品时，以现存本机副本初始化项目；旧版若只保存了抠图结果，无法恢复其已丢失的原图，应如实提示。

## 4. 自动动效的质量约束

1. **主体准备**：先判定图片原有透明度；对纯色背景可复用 `cutout.js`，不确定时要求用户确认或修边。不要对带明显矩形背景的整张照片默认做网格形变。
2. **网格**：按透明主体边界生成有限密度的网格；脚底与接触面为固定区，头脸附近只允许小幅、连续的整体位移。动作参数相位由单一时间轴驱动，不靠帧计数累加，避免卡顿后的相位漂移。
3. **状态**：`idle` 为循环呼吸与轻摆；`walk` 先使用整体移动与保守的重心反馈；`tap/play/nap` 用有限时长的覆盖动作并平滑回到 idle。没有可靠图层时不假装能独立运动四肢。
4. **时间与清理**：只在可见且允许自主动画时请求动画帧；隐藏、安静、专注、减少动态效果、角色切换或窗口销毁时停止调度并释放纹理。拖拽优先于自主动作。
5. **资源上限**：导入时已有 5 MB 文件限制，需另加解码像素上限与长边缩放，避免压缩很小但尺寸巨大的图片占满 GPU。纹理在进入预览时上传一次，市场列表只显示缩略图。
6. **同源预览**：工坊和桌面使用同一 `AnimatedPet` 渲染组件及动作参数解释器；市场卡片、小窝静态场景仍可使用缩略图，必要时小窝只启用低频动画。
7. **现成动画**：GIF/动态 WebP/APNG 不做静态抠图；多帧图先统一透明画布、主体基线与播放时长；视频默认静音，只接受能在目标系统正确解码并保留透明度的素材直接使用。

## 5. 实施切口

### P0 的代码边界

- `src/electron/main.js`：导入与项目保存 IPC，导入完成后仍使用现有角色切换通知。
- `src/electron/pet-core.js`：在读取入口区分静态与多帧图片；动图保留原文件，不送入静态抠图。
- `src/electron/settings-store.js`：项目记录的最小迁移；用户数据写入只在主进程。
- `src/electron/animation/`：新增作品读取与动作参数纯逻辑，现有 `artwork-source.js` 保留静态与视频通道。
- `src/ui/market/`：把导入、抠图确认、动作预览、保存合成一个制作步骤。
- `src/ui/shared/`：共用单图动效渲染器、动作契约和生命周期管理。
- `src/ui/pet/`：仅对具有动效项目的自定义静态宠物启用新渲染器；内置角色与 GIF 继续现有路径。

### 验证顺序

1. 纯函数测试覆盖项目迁移、参数边界、动作时间轴及原子保存失败后的回退。
2. Electron smoke test 覆盖导入透明图、GIF、动态 WebP、APNG，预览、保存并使用、重启恢复、关闭动效、旧作品保持原路径，以及页面错误；P1 再覆盖帧序列乱序、变时长和透明/不透明视频。
3. 对同一素材在编辑预览、透明桌面窗口、深浅背景、小窝中截图比较；用真实 macOS/Windows 机器记录长时间帧间隔、CPU/GPU 与内存。`npm run check` 和 `npm test` 通过并不等于实机流畅性达标。
4. 未达到观感或性能门槛时，保留静态导入为默认可用路径，不将实验性动效标成已完成。
