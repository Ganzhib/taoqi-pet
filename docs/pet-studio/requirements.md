# 宠物工坊：把静态图和现成动画变成桌宠

> 状态：部分实现。v0.4.6 已提供桌宠与菜单制作入口，并将发现伙伴、制作宠物、我的宠物整合到同一窗口；动效编辑、连续帧和视频导入仍按本文规划。实现边界见 [技术架构](architecture.md)。当前已上线能力以 README 为准。

## 1. 产品判断

淘气桌宠的主线应从“挑一只免费宠物”变成“得到一只属于自己的、会陪伴的宠物”。用户已有自己的图片，但当前导入流程只完成了抠图、保存和切换；桌面上的自定义静态图主要靠整张图片的 CSS 呼吸与互动变换，看起来仍像一张会晃动的贴纸。

目标是在**桌面应用内**完成「选素材 → 检查主体与动作 → 保存并立即使用 → 随时继续编辑」。第一版无需账号、网络、外部生成服务或专业动画知识。官网先解释能力和提供下载，不另建一套与桌面数据不互通的在线编辑器。

用户的起点不止一张静态图。已经画好动作的人应能导入 GIF、动态 WebP、APNG、多张连续帧，或符合透明播放条件的视频，尽量保留原有动作；自动形变只服务于没有动画的单张图。工坊先识别素材，再展示合适的编辑步骤，而不是强迫每种素材经过抠图和网格绑定。

单张图片缺少被遮挡部位的信息。自动模式可以做自然的呼吸、重心移动与轻微摇摆，不能承诺可靠地自动抬手、转身或生成新的面部表情。需要明显肢体动作时，进入有图层、锚点和动作编辑的进阶模式；生成式补全未来只能作为用户主动选择、可预览的辅助步骤。

## 2. 用户流程与信息架构

1. **发现**：首次启动仍直接出现默认桌宠。用户从宠物菜单或 `M` 打开“宠物工坊”，不强迫先创作。
2. **制作**：在同一入口选择“单张图片”“现成动图/视频”“多帧图片”或“从模板开始”。单张图检查抠图与自动动效；现成动画检查透明度和循环；多帧图检查顺序、对齐与时长。
3. **预览**：桌面尺寸、深浅背景、静止/走动/点击/安静模式四种状态可在同一预览区切换；按素材类型调整幅度、速度或循环点。预览与实际桌宠共用渲染器，避免“编辑器好看，桌面变样”。
4. **使用**：点击“保存并使用”后，作品进入“我的宠物”，桌面立即切换。制作过程无需另行导出、安装素材包或重启应用。
5. **继续修改**：作品可以重新打开，修改名字、主体边缘与动作参数；保存前能比较旧版和新版。删除前说明会删除哪份本地副本。

工坊已使用三个清晰区域：**发现伙伴**（现有内置角色）、**制作宠物**（现有导入与模板入口）、**我的宠物**（已保存作品及改名、删除、选用）。后续编辑与统一预览仍待实现；现有快捷键和已保存角色 ID 保持可用。

### 素材入口的产品规则

| 素材 | 优先路径 | 用户可调整 | 使用前的关键检查 |
| --- | --- | --- | --- |
| 单张 PNG/JPG/WebP 或模板 | 透明主体 + 保守的自动动效 | 修边、幅度、动作开关 | 主体是否完整，五官与脚底是否变形。 |
| GIF、动态 WebP、APNG | 保留原始帧并直接预览 | 循环、速度、缩放；进阶版可裁剪 | 是否带矩形背景、画质与循环接缝。 |
| 多张 PNG/WebP 连续帧 | 排序、统一画布与脚底基线，再作为逐帧作品播放 | 帧顺序、每帧时长、循环段、预览帧 | 缺帧、尺寸不一致、角色抖动和透明边缘。 |
| 透明 WebM 视频 | 验证可播放与 alpha 后使用 | 静音、裁剪、循环点、缩放 | 解码、透明度、首尾接缝、资源占用。 |
| 普通 MP4/MOV 等视频 | 先检查是否有可保留的透明主体；不合格时说明处理步骤 | 后续提供用户确认的离线处理 | 不能把不透明矩形直接伪装成透明桌宠。 |

多个素材可以映射到同一只宠物的 `idle / walk / tap / play / nap` 状态；只有一段素材时先作为待机循环，其他互动继续使用现有通用反馈。动作素材的缺失不阻止保存并使用。

## 3. 现有功能的取舍与整合

| 现有能力 | 决定 | 整合方式 |
| --- | --- | --- |
| 八位免费内置伙伴 | 保留，作为立即可用的起点 | 从“市场商品”改为“发现伙伴”的示例和灵感；维持免费、离线可用。 |
| 图片导入与自动抠图 | 升级为按素材分流的制作入口 | 静态图进入主体处理与自动动效；已有动画保留原帧，进入循环与透明度预览。 |
| 小猫/小龙/团子可视化捏宠 | 并入“从模板开始” | 模板和导入作品共用保存、预览、选用与管理路径，不再占一个与导入平行的主入口。 |
| “宠物市场”的“打工中/沙雕日常”分类 | 逐步收起 | 当前八位角色可以保留编辑标签，但主导航不再靠内容分类承担“制作/管理”功能。 |
| 我的创作、改名、删除 | 保留并扩展 | 变为“我的宠物”；增加继续编辑、版本恢复和动效开关。旧作品无需手动迁移才能使用。 |
| 点击、喂食、玩耍、夸奖和低频自主行为 | 保留，统一动作语义 | 每个宠物按同一事件表响应；没有专属动作时使用明确的通用反馈，不强行把单张图扭成肢体动作。 |
| 咕咕嘎嘎九套造型 | 保留角色专属体验 | 不把现有九套逐帧素材当成所有导入图的通用能力；未来装扮编辑成熟后再统一入口。 |
| 星星/蝴蝶结/小花装扮 | 保留，延后进编辑器 | 首期仍可在桌面菜单使用；待锚点与遮挡关系稳定后并入工坊的装扮步骤。 |
| 淘气小窝、家具、抓鱼 | 保留独立场景，暂停扩量 | 小窝使用同一宠物作品与动作能力；先解决新作品在小窝的显示与性能，不增加新的家具或游戏机制。 |
| 原地陪伴/自由散步/跟随鼠标、安静/专注/置顶/大小 | 保留为桌面偏好 | 工坊只预览相关状态，不把系统级窗口设置塞进角色编辑步骤。安静与减少动态效果优先于作品动效设置。 |
| 淘气工具铺 | 保留用户主动打开 | 与宠物制作无绑定、无自动导流；宠物功能继续永久免费。 |

## 4. 版本切分与完成门槛

### P0：素材导入即用

- 单张静态图导入后，先保留原图副本，再做可检查的抠图。透明图无需重复抠图；不适合自动处理的图片进入修边或保留静态的选择。
- 自动动效仅覆盖低风险的呼吸、重心和摇摆，保持脚底接地与主体轮廓稳定。用户可调幅度或关闭动效。
- GIF、动态 WebP 和 APNG 保留原始帧、循环和透明信息；不进入单图抠图或网格形变。动图没有透明主体时，预览中明确显示矩形背景问题。
- “保存并使用”在同一次流程内切换桌面角色。已有动画先直接用，静态图则预览自动动效后使用。
- 旧版导入作品继续显示；可逐个打开并升级，不在后台批量重写用户文件。

**验收**：首次使用者在一条顺畅路径内把合适的图片或动图变成桌宠；导入动图不会丢帧或被压成静态首帧；预览与桌面结果一致；在深色、浅色和杂色壁纸上无明显白边、矩形背景、脚底滑动或五官拉扯。关闭自动动效后单图素材与静态导入一致。

### P1：可编辑的宠物作品

- 工坊重组为“发现/制作/我的宠物”；导入与模板使用同一作品模型。
- 增加主体修边、锚点与动作强度编辑，支持重开项目、撤销最近操作和保存前预览。
- 支持多选连续帧并调整顺序、基线、逐帧时长与循环段；支持已验证透明度的 WebM 视频直接作为桌宠素材。
- 自定义宠物的点击、玩耍、打盹状态能用可解释的动作预设衔接；小窝复用同一作品。

**验收**：重新打开作品后参数和预览一致；旧版设置、角色选择、改名与删除不回退；键盘可完成主要操作。

### P2：视频处理、分层动作与可选分享

- 用户可把头、身体、手脚等分成图层，设置关节与遮挡，再制作抬手、走路等动作。没有分层的单图仍走 P0 路径。
- 对 MP4/MOV 等常见视频提供经过质量门槛的离线转换；若素材没有透明主体，需先由用户确认背景处理结果。音频默认不进入桌宠播放。
- 导出可携带原图、透明素材、绑定参数与动作的作品包；分享必须由用户主动触发并明确素材权利。
- 只有确实存在跨设备同步或社区分发需求时才设计账号、服务端与审核。此阶段之前不把作品静默上传。

## 5. 质量、隐私与成功指标

- **观感**：重点检查头脸、细线、文字和脚底；无法稳定形变时允许静态使用，不能为了“有动画”牺牲原图。
- **逐帧/视频**：保留原始帧顺序与时间；多帧素材对齐脚底，循环点不明显闪断，视频不出现矩形背景或意外声音。
- **流畅**：目标设备上连续播放 2 分钟，动画帧间隔的第 95 百分位不超过 20 ms；拖动与点击不被动画任务阻塞。记录 macOS arm64/x64 与 Windows x64 实机结果，CI 只验证功能链路。
- **功耗**：窗口隐藏、安静模式、专注与系统“减少动态效果”时暂停或降级自主动画；资源在角色切换与窗口关闭时释放。
- **隐私**：图片、蒙版与作品文件默认只在本机。任何在线生成或分享都应是单独的用户动作，先展示将发送的内容。
- **产品指标**：用本地可复现的任务验收，不先接入统计 SDK。记录任务是否完成、制作耗时、用户是否能辨认“静态/自动/分层”的能力边界；若未来要收集匿名数据，先另行设计同意机制。
