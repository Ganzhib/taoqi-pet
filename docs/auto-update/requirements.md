# 自动更新需求

## 目标

淘气桌宠永久免费。安装版在新版本发布后主动提示用户，减少重复下载和手动覆盖安装。更新检查仅请求本项目公开的 GitHub Releases，不上传宠物图片、设置或设备身份信息。

## 用户流程

1. 已打包的应用启动约 15 秒后检查一次，此后每 6 小时检查一次；托盘和宠物右键菜单提供“检查更新…”。
2. Windows 安装版发现新版后在后台下载。完成时显示系统通知与宠物提示，并在菜单显示“重启安装”。用户可立即重启，也可稍后退出时安装。
3. Windows 便携版和当前未签名的 macOS 预览版发现新版后显示通知与下载入口，用户从官方 Release 获取对应安装包。
4. 安静模式下不主动弹出系统通知或宠物提示；手动检查仍返回明确结果。断网时自动检查静默失败，手动检查显示失败原因的简短提示。
5. 正式版只接收后续正式版，不能自动升级到 preview 预览版；预览版继续接收后续预览版，并可在正式版发布后升级到正式版。

## 平台范围

| 平台与分发形态 | 发现/通知 | 后台下载 | 原地安装 |
| --- | --- | --- | --- |
| Windows NSIS 安装版 | 是 | 是 | 是，退出或确认重启时 |
| Windows 便携版 | 是 | 否 | 否，手动下载 |
| macOS 未签名预览版 | 是 | 否 | 否，手动下载 |
| macOS 完成开发者签名后 | 是 | 后续开启 | 后续开启 |

Electron 和 electron-builder 均要求 macOS 应用签名后才能自动安装更新。不要尝试在未签名版本中替换应用程序目录。

## 发布与验收

- 首个内置更新器的版本为 v0.3.0-preview.2。此前已安装的 preview.1 没有更新器，需要手动升级一次。
- 发布工作流同时上传 Windows/macOS 安装包、ZIP 与更新清单；清单和安装包必须来自同一次构建，Release 在文件齐备后才公开。工作流分两条：`.github/workflows/release.yml` 发布正式版（不带 prerelease 标记），推送与 `package.json` 版本一致的 `v*` 标签或手动运行均可触发；`.github/workflows/release-preview.yml` 发布预览版并保持手动触发。
- 正式版使用 `latest.yml` / `latest-mac.yml`，预览版使用 `preview.yml` / `preview-mac.yml`，两种发布不能覆盖对方的清单。预览版客户端检查公开 Release 后，按候选版本临时选择 preview 或 latest 渠道，因此既能接收后续预览版，也能转入正式版。
- 版本检查只接受本项目格式 `v主.次.修-preview.序号` 或正式版；忽略草稿和无效标签。正式版客户端同时忽略 GitHub 标记为 prerelease 的 Release 和带 `-preview` 后缀的版本，避免发布元数据配置错误时串入预览渠道。
- v0.3.2 是首个隔离正式/预览渠道的版本。v0.3.0 与 v0.3.1 的正式安装版已固定到 preview 渠道，无法通过原有更新器安全切换到 latest，需要手动安装一次 v0.3.2 或之后的正式版。
- `npm run check`、`npm test`、Electron smoke 与 GitHub Actions 构建通过后，才视为代码和打包验收。Windows 从旧安装版到下一版的真实原地更新，仍需在 Windows 设备上单独验收。
